# 05 — Live on Render

_Date: 2026-10-17_

**API:** https://aanchol-api.onrender.com (health check: `/api/health`)

## What was done
- **Blueprint:** `render.yaml` describes the service: `aanchol-api`, Node 22, the free plan, region Singapore (closest to Bangladesh).
  - It builds with `npm ci --omit=dev` and starts with `npm start`.
  - Render watches `/api/health`.
  - Every push to `main` deploys automatically.
- **Environment on Render** (Dashboard → aanchol-api → Environment):
  - `MONGODB_URI`, `CLOUDINARY_*`: copied from the local `.env`.
  - `CLIENT_ORIGIN` = `https://aanchol-client.vercel.app` (comma-separate more later, e.g. your own domain).
  - `JWT_SECRET`: generated by Render. It's different from the local one, so admin logins don't carry over between local and live.
  - `NODE_ENV=production`, `NODE_VERSION=22`.
- **Fix: trailing slash in `CLIENT_ORIGIN`.**
  - The dashboard value ended in `/`, so browsers were refused because they send the origin without one.
  - `src/config/env.js` now removes trailing slashes and empty entries.
- **Keep awake:**
  - Render's free plan sleeps after 15 minutes idle, and waking takes about 50 seconds.
  - `.github/workflows/keep-awake.yml` pings `/api/health` every 10 minutes. It's free because the repo is public, and if the API is down the run fails and GitHub emails you.
  - GitHub may delay scheduled runs, so the first visitor after a quiet spell can occasionally wait. For more reliable pings, add an UptimeRobot monitor (5-minute interval) to the same URL.
- **Atlas:** Network Access must include `0.0.0.0/0`, because Render's free plan has no fixed IP. The database password still protects the data.

## Changing things later
- **New setting:** add it in the Render dashboard; the service restarts by itself.
- **Your own domain:** add it to `CLIENT_ORIGIN`, e.g. `https://aanchol-client.vercel.app,https://aanchol.com,https://www.aanchol.com`.
- **Logs:** Render dashboard → aanchol-api → Logs.
